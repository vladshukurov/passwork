# Как работать с проектом через нейросети

Сайт собирался вместе с ИИ-агентами: сначала Codex (OpenAI), потом Claude Code (Anthropic).
Figma-файл правили через официальный Figma MCP. Продолжать можно любым агентом, который
умеет читать и править файлы в папке проекта. Ниже — как настроить его и как формулировать
задачи, чтобы результат был предсказуемым.

## Инструменты

| Инструмент | Для чего | Как подключить |
| --- | --- | --- |
| [Claude Code](https://claude.com/claude-code) | правки кода, анимаций, вёрстки по макету, работа с Figma | CLI, десктоп-приложение или расширение для VS Code / JetBrains; откройте папку проекта |
| [Cursor](https://cursor.com) | то же в виде редактора | откройте папку проекта |
| [Codex](https://openai.com/codex) | то же | CLI или приложение; откройте папку проекта |
| Figma MCP (официальный MCP-сервер Figma) | чтение макетов и правки Figma-файла из агента | подключите сервер Figma в настройках MCP агента (инструкция — в справке Figma, раздел MCP) и войдите своим аккаунтом Figma |

Контекст проекта агент берёт сам из [`AGENTS.md`](../AGENTS.md) (Claude Code — через
`CLAUDE.md`): стек, команды, структуру и правила дизайна. Держите этот файл актуальным.
Если команда договорилась о новом правиле, допишите его туда, и оно будет действовать
во всех следующих сессиях.

Личные ключи и аккаунты разработчиков в проекте не используются. Каждый работает со своей
подпиской на агента и своим аккаунтом Figma.

## Требования для Figma MCP

- Нужно место **Full** или **Dev** в команде Figma, которой принадлежит файл. На месте
  View лимит запросов MCP очень маленький, а редактировать файл нельзя.
- Скрипты Figma не видят коммерческий шрифт Museo Sans Cyrl, поэтому правка текстовых
  слоёв из агента падает с ошибкой загрузки шрифта. Обходной путь:
  1. на время работы агента переключите переменные `font/family/sans` и `font/family/ui`
     в коллекции Primitives на `Inter`, а `font/style/*` — на `Regular` / `Medium` / `Bold`;
  2. после работы верните `Museo Sans Cyrl` и стиль `500`.
  Текстовые стили привязаны к этим переменным, поэтому весь файл переключится разом.

## Как ставить задачу

Что лучше всего работало на этом проекте:

1. **Одна задача — одна сессия и одна ветка.** Попросите агента создать ветку, а в конце
   запустить `npm test` и `npm run build`.
2. **Покажите, а не только расскажите.** Приложите скриншот «как сейчас» и ссылку на фрейм
   Figma «как надо». Со ссылкой на конкретный узел агент сам прочитает отступы, цвета и
   стили.
3. **Называйте блок и файл.** «В блоке «Цены» (`src/sections/Pricing.jsx`)…» — агент не
   будет искать по всему проекту и не заденет соседние блоки.
4. **Конкретные числа вместо оценок.** «Подзаголовок в интро 16/26, заголовок карточки
   28 px, высоты карточек одинаковые» работает лучше, чем «сделай аккуратнее».
5. **Пусть проверит глазами.** Попросите запустить сайт, посмотреть на ширинах
   1440 / 800 / 390 и строго оценить результат до того, как показывать. Так ловятся сдвиги
   и наложения.
6. **Большой фидбэк — списком.** Пронумеруйте пункты и попросите разбить их на задачи и
   ничего не потерять. Агент отчитается по каждому.
7. **Точка отката.** Перед рискованной переделкой попросите сохранить текущий вариант
   (коммит или ветку), чтобы можно было вернуться.
8. **Не давайте придумывать контент.** Тексты и цифры — с passwork.ru или из макета; так и
   пишите в задаче.
9. **Анимации описывайте ощущением и ограничением.** Например: «мягко, без прыжков, один
   жест, тайминги из токенов». Затем попросите сравнить с соседними блоками — анимации
   на сайте должны ощущаться одинаково.

Готовые формулировки по типам задач — в [`docs/prompts/`](prompts/README.md).

## Проверка результата перед слиянием

- `npm test`, `npm run build`, при изменении поведения — `npm run smoke`.
- Посмотрите diff: правка должна затрагивать только нужные файлы.
- Пройдите по чек-листу из [motion.md](motion.md#проверка-после-изменений).
- Откройте PR: GitHub Actions повторит проверки, а превью Vercel даст ссылку для просмотра.
